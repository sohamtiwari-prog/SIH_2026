The problem

The same crater, two different suns

On an airless body the only thing that changes between two views of the same terrain is the sun. A crater lit from the east has a bright west wall and a shadowed east wall — lit from the west, the pattern inverts. SIFT-style descriptors are gradient-orientation histograms, so a 180° sun-azimuth change flips every gradient and the match collapses. It isn't a tuning problem — it's structural.

SOURCE · OHRC-class, 0.32 m/px
sun az 135° · el 35°
REFERENCE · NAC-class, 0.50 m/px
sun az 255° · el 22° · Δaz = 120°
Same DEM, same crater field, same albedo — rendered twice under a 120° sun-azimuth change plus a 6° rotation and a 1.56:1 scale difference. Every pixel of appearance has changed; nothing about the geometry has.
Approach

A six-stage registration cascade

Every stage is a flag on PipelineConfig, so the ablation study below can isolate exactly which stage a result depends on.

Metadata scale prior

Both PDS labels carry the map-projected ground sample distance, so the scale ratio is known, not something to discover. Pre-resampling the source to the reference GSD removes the single largest source of matcher failure before a single feature is found. Skipping it is the most common design error — see the ablation below.

use_scale_prior

Illumination transform

Phase congruency (Kovesi), not raw intensity. At a step or ridge, local frequency components arrive in phase regardless of the sign of the gradient — invariant to the sun crossing the sky.

phase_congruency()

Detect + describe

RIFT keypoints on the phase-congruency map with a Maximum-Index-Map descriptor, or a dense correlation grid when appearance survives better than repeatable keypoints do (it usually does — see Validation).

rift · dense · hybrid

Match + robust geometry

Mutual nearest-neighbour + Lowe ratio, then MAGSAC++ climbing a similarity→affine→homography ladder — accepting a richer model only if it keeps enough inliers, so a homography never folds the image to fit noise.

estimate_progressive()

Sub-pixel refinement

Upsampled-DFT phase correlation (Guizar-Sicairos) per tie point. Descriptor matching localises to about ±1 px at best; this is where sub-pixel accuracy is actually won.

refine_subpixel()

Uniformity enforcement

Block-cap + adaptive non-maximal suppression, then a refit. Tie points cluster on textured terrain and vanish on smooth mare — a model fitted only to the clustered points looks excellent and drifts everywhere else.

enforce_uniform()

Metrics

Reprojection RMSE with a bootstrap confidence interval, inlier ratio, uniformity, and residual structure (Moran’s I) — the last of which asks not "how big is the error" but "is it spatially structured", which is what a wrong model looks like.

metrics.py
Validation

Measured against exact synthetic ground truth

Hand-digitised tie points on real imagery carry 0.5–2 px of operator noise — the same order as the sub-pixel accuracy this claims, so they can't certify it. Every number below comes from synth.py: a physically-rendered virtual Moon (crater DEM, cast shadows, Lunar-Lambert photometry, per-sensor MTF/noise) imaged twice under different sun angles and sensor models, with the exact relating homography known analytically.

E3 · Ablation — which stage is load-bearing?

Δaz = 90°, the hardest single condition tested

Disabling the metadata scale prior alone degrades the median error from sub-pixel to hundreds of pixels — nothing else in the cascade comes close. (no_uniformity / no_subpixel track full almost exactly here because the dense pipeline's own area-correlation step already is the sub-pixel estimator and already guarantees a uniform grid by construction — those two flags only change behaviour on the sparse/RIFT path.)

Deliverable

Runnable, in three ways

Registered product + tie points + evaluation metrics, from a real OHRC/TMC-2/IIRS product or the synthetic harness above.

Register a real pair
# PDS4 (Chandrayaan-2), PDS3 (LRO NAC), or GeoTIFF — auto-detected $ lunareg register --src ohrc_strip.xml --ref lro_nac_mosaic.tif --method hybrid
Single file, no install
# everything on this page, one script $ pip install -r requirements.txt $ python scripts/lunareg_all_in_one.py register --src A.xml --ref B.tif
Reproduce this page's numbers
$ lunareg experiments --out-dir outputs # E1-E4 $ lunareg analyse --out-dir outputs # -> dashboard_data.json $ lunareg dashboard --out-dir outputs # -> interactive HTML
Output: product.json (homography, every match point, evaluation metrics) + warped_source.png + a checkerboard QC mosaic. 43 pytest cases cover the sub-pixel estimator, robust homography fitting, the real-product readers, and the full pipeline against ground truth.
